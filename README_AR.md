# Novex Store — إعداد لوحة المالك برمز خاص

المتجر العام يبقى كما هو، ويمكن للزوار مشاهدة المنتجات والطلب عبر WhatsApp. لوحة المالك لا تطلب حساب Supabase أو بريدًا إلكترونيًا؛ تستعمل رمزًا سريًا يتحقق منه الخادم، ويمكن إضافة حتى 10 صور لكل منتج.

## مهم قبل النشر

رمز المالك لا يوضع داخل `config.js` أو أي ملف يصل للزوار. التحقق يتم داخل Supabase Edge Function. لا تضع `service_role` أو `sb_secret` في ملفات الواجهة.

## 1) إعداد config.js

ضع مفتاح Supabase العام (Publishable أو anon) في `SUPABASE_ANON_KEY`. اترك `OWNER_FUNCTION_URL` على رابط دالة `owner-products` لمشروعك؛ إذا كان مشروعك مختلفًا بدّل جزء اسم المشروع في الرابط.

## 2) تحديث قاعدة البيانات

افتح Supabase → SQL Editor، ثم نفّذ كامل ملف `supabase.sql`. سيضيف عمود `image_urls` لدعم الصور المتعددة، ويمنع الكتابة المباشرة من المتصفح؛ التعديلات تمر عبر الدالة.

## 3) نشر Edge Function

تحتاج Supabase CLI مثبتًا ومسجّل الدخول. من مجلد المشروع نفّذ:

```bash
supabase functions deploy owner-products --project-ref zxfnuqoioidlhpojskwe
```

إذا كان مشروعك في مجلد Supabase مختلف، تأكد أن المسار `supabase/functions/owner-products/index.ts` موجود ضمن المشروع الذي تنشره.

## 4) ضبط أسرار الخادم

أنشئ رمزًا قويًا وطويلًا خاصًا بك، ثم أضفه كسرّ للخادم (بدّل القيمة بمفتاحك أنت):

```bash
supabase secrets set OWNER_ACCESS_CODE="ضع-هنا-رمزاً-طويلاً-خاصاً-بك" --project-ref zxfnuqoioidlhpojskwe
```

يجب أن تكون أسرار `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` متاحة للدالة كما يوفّرها Supabase تلقائيًا. لا تشارك رمز المالك مع أحد.

## 5) النشر والتجربة

ارفع ملفات المجلد `Novex_Store` إلى الاستضافة. افتح `admin.html`، أدخل رمز المالك، ثم أضف الاسم والسعر والوصف واختر حتى 10 صور. عند تعديل منتج، إذا لم تختر صورًا جديدة تبقى الصور الحالية. اختبر الإضافة والتعديل والحذف من المتجر المنشور.

## حدود الصور

- حتى 10 صور للمنتج.
- JPG / PNG / WebP فقط.
- 5MB كحد أقصى لكل صورة.

## ملاحظة أمان

لا تستخدم اسمًا ظاهرًا فقط كحماية؛ أي زائر يستطيع تقليده. رمز المالك يتم التحقق منه في Edge Function، لكن يجب إبقاء الرمز سريًا وعدم وضعه داخل ملفات الموقع.
